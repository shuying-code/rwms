# rwms (Rust Warehouse Management System) User Manual

> Applies to v1.0.0 / v0.1.0+.
> A guide for end users and admins: launch, login, business modules, API usage, data & config, FAQ.
> Overview: [README](../README.en.md). Deployment: [DEPLOYMENT](../DEPLOYMENT.md).

---

## 1. Overview

rwms is a **local, single-binary, zero external-database** warehouse management system (WMS) written in **Rust + Axum + SeaORM**. It embeds **SQLite**, ships a complete Web frontend (HTML/CSS/JS) with JWT auth, and is **ready to use, single-binary deployable** on Windows / macOS / Linux.

---

## 2. Install & Launch

### Run directly
```bash
rwms                 # start service (default 0.0.0.0:8080)
```
On startup it creates `wms.db` in the database directory and auto-creates tables (first run does schema creation & migration).

### Windows installer
Run `rwms-setup-*.exe` and follow the wizard (optional desktop shortcut / auto-start), then launch from the Start menu or desktop shortcut. See [DEPLOYMENT](../DEPLOYMENT.md).

### Container
```bash
docker run --rm -p 8080:8080 -v rwms-data:/wms ghcr.io/shuying-code/rwms:latest
```

---

## 3. Access & Login

1. Open <http://localhost:8080/login.html>.
2. Default account: `admin` / `admin` (**change password and `JWT_SECRET` in production**).
3. After login you land on the dashboard; use the side/top menu for each module.
4. Health check: <http://localhost:8080/health> (returns `{"status":"UP"}`).

---

## 4. Modules

| Page | File | Description |
|---|---|---|
| Login | `login.html` | Log in to obtain JWT |
| Home | `index.html` | Dashboard |
| Materials | `material.html` | List / detail / add / update / delete (paged) |
| Categories | `category.html` | Material category CRUD |
| Warehouses | `warehouse.html` | Multi-warehouse info |
| Suppliers | `supplier.html` | Supplier info |
| Customers | `customer.html` | Customer info |
| In-orders | `inorder.html` | Create (with items) / list / detail / audit / delete / items |
| Out-orders | `outorder.html` | Create (with items) / list / detail / audit / delete / items |
| Stock | `stock.html` | Multi-condition filtered, paged stock query |

### Typical workflow
1. **Base data**: maintain Categories / Warehouses / Suppliers / Customers first.
2. **Material master**: add materials (linked to category, unit, etc.).
3. **Inbound**: create an in-order (header + items) → submit → **audit (approve/reject)**; approval increases stock.
4. **Outbound**: create an out-order → submit → **audit**; approval decreases stock.
5. **Stock query**: filter by material/warehouse and page through results.

## 5. Authentication

- Login `POST /api/login` to get a JWT; logout `POST /api/logout`.
- Except public routes, all endpoints require `Authorization: Bearer <token>` (validated by middleware).
- **Public routes**: `GET /`, `GET /health`, `POST /api/login`.

---

## 6. API Overview

Protected routes require `Authorization: Bearer <token>`:

| Resource | Endpoints |
|---|---|
| Logout | `POST /api/logout` |
| Materials | `GET/POST /api/materials`, `GET/DELETE /api/materials/:id`, `POST /api/materials/update` |
| Categories | `GET/POST /api/categories`, `GET/DELETE /api/categories/:id`, `POST /api/categories/update` |
| Warehouses | `GET/POST /api/warehouses`, `GET/DELETE /api/warehouses/:id`, `POST /api/warehouses/update` |
| Suppliers | `GET/POST /api/suppliers`, `GET/DELETE /api/suppliers/:id`, `POST /api/suppliers/update` |
| Customers | `GET/POST /api/customers`, `GET/DELETE /api/customers/:id`, `POST /api/customers/update` |
| In-orders | `GET/POST /api/in-orders`, `GET/DELETE /api/in-orders/:id`, `POST /api/in-orders/audit`, `GET /api/in-orders/:id/items` |
| Out-orders | `GET/POST /api/out-orders`, `GET/DELETE /api/out-orders/:id`, `POST /api/out-orders/audit`, `GET /api/out-orders/:id/items` |
| Stock | `GET /api/stocks` |

Examples:
```bash
curl -s -X POST http://localhost:8080/api/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin"}'

curl -s http://localhost:8080/api/materials -H "Authorization: Bearer <token>"
```

## 7. Configuration

Config comes from `application.yml` (switch via `APP_ENV`); common env vars:

| Variable | Description |
|---|---|
| `PORT` | Listen port (default `server.port` in `application.yml`, i.e. 8080) |
| `JWT_SECRET` | JWT secret (overrides `jwt.secret`; **required in production**) |
| `APP_ENV` | Environment tag (dev / test / prod) |
| `RUST_LOG` | Log level filter (e.g. `info`, `debug`) |

---

## 8. Database & Data Directory

| Platform | Path |
|---|---|
| Windows | `C:\ProgramData\wms\wms.db` |
| Linux / macOS | `/wms/wms.db` (Docker: mount a volume at `/wms`) |

Logs are in the same directory (`wms.log`, daily rotation). **Backup**: copy `wms.db` (and `wms.log`); restore by replacing them.

---

## 9. FAQ

**Need to install a database?** No. Embedded SQLite; `wms.db` and tables are created on first run.
**Default account?** `admin` / `admin`. Change password and `JWT_SECRET` before production use.
**Port in use?** Start with `PORT=9090` (or edit `server.port`).
**Where is the data directory?** Windows `C:\ProgramData\wms`; Linux/macOS `/wms`.
**How to stop?** Close the window, or end the `rwms` process.
